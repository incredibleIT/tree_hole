# 产品需求文档 - 以外

**作者：** Yang
**日期：** 2026-07-11

## 执行摘要

「以外」是一个公益开源的 Web 应用，为所有有过“错过”经历的人创造一个安静、克制、永久的故事空间。每个用户一生最多只能落笔三篇故事，讲述与错过的人之间未完成的话。故事一旦落笔，永远清晰存在，不可删除，只能选择“合上”。

平台的核心问题：人总会错过某个人——没有说出口的话、没有转身的背影、以为来日方长的“下次再说”。但社交平台太嘈杂，树洞应用把遗憾变成娱乐，日记缺少被见证的仪式感，写信无处寄送。错过的情感无处安放。

「以外」的解决方案：创造一个专属的情感场所。通过“落笔”仪式（一分钟静默 → 三个温和问题 → 笔落纸声）将发布行为重塑为告别仪式。极致稀缺（一生三篇）确保每一篇都是经过深思的、真实的。反社交设计（无评论、无关注、无搜索、无信息流）保护故事的私密性和重量感。

### 产品独特性

「以外」与所有现有内容平台的根本区别在于设计哲学相反：现有产品追求更多内容和更高留存，「以外」的设计目标是让用户用得越少越好。三篇用完就“毕业”，平台不需要用户回来，只希望每一篇都是真诚的。

核心洞察：**稀缺本身就是价值。** 当平台限制你只能说三句话时，你说的每一句都会是经过深思的、真实的。这种价值观不是产品逻辑，而是对“不可替代”的信仰。

### 项目分类

- **项目类型：** Web 应用（Web 优先，跨平台浏览器访问）
- **领域：** 通用（情感表达平台，无特定行业监管要求）
- **复杂度：** 低（标准 Web 技术栈，技术挑战集中在仪式化交互和永久存储）
- **项目背景：** 全新项目（目前无现有代码）
- **项目性质：** 公益开源，独立开发者维护，代码托管于 GitHub

## 成功标准

### 用户成功

- **落笔后轻松感：** 用户完成落笔后，主观感受“轻了一点”（通过简单的落笔后反馈收集）
- **内容深度：** 平均写作时长 30 分钟+，说明用户在认真对待落笔过程
- **完成率：** 进入落笔仪式流程的用户中，完成落笔的比例 ≥ 60%（排除中途放弃）
- **草稿转化率：** 创建了草稿的用户中，最终落笔的比例（衡量“深思后行动”）

### 项目成功（公益开源）

- **概念验证阶段：** 等待列表积累 1000+ 邮箱（验证社会需求）
- **落笔率：** 进入平台的人中，5-10% 最终完成落笔
- **自然传播：** 用户在社交媒体上自发提及「以外」（无需付费推广）
- **社区贡献：** GitHub 仓库星标数、外部代码贡献者数量（长期健康指标）
- **内容质量：** 平台故事被外部引用、分享、讨论的频率

### 技术成功

- **永久存储可靠性：** 故事数据零丢失，99.9% 可用性
- **页面加载速度：** 首屏加载 < 2 秒（情感体验不能被技术问题打断）
- **仪式流程流畅性：** 落笔仪式的动画和音效在主流浏览器上正常运行率 > 95%
- **反截图机制：** 在主流浏览器上阻止或降低截图成功率
- **部署稳定性：** 独立开发者可独立维护，无单点故障

### 可衡量成果

| 指标 | 概念验证阶段目标 | 第二版目标 |
|------|-----------------|------------|
| 等待列表 | 1000+ 邮箱 | 不适用（已开放） |
| 日活跃故事阅读数 | 100+ | 500+ |
| 落笔完成率 | 不适用 | 60%+ |
| 平均写作时长 | 不适用 | 30 分钟+ |
| GitHub 星标数 | 100+ | 500+ |

## 产品范围

产品分三个阶段递进开发：概念验证网站（最小可行产品）→ 开放写作（增长版）→ 远期扩展。详细功能列表见「项目范围界定与分阶段开发」章节。

## 用户旅程

### 旅程一：小晚 —— 第一次落笔（核心体验路径）

**开场：** 小晚，24 岁，深夜刷手机时看到朋友转发的一条链接：“每天只有一篇故事，读完就没了”。她点进去，看到一个极简页面，只有一篇匿名故事。她读完后眼眶湿润——那个人写的，和她想说的几乎一样。页面底部有一个输入框：“我想落笔”。她输入了邮箱。

**上升：** 三天后，她收到一封邮件：“你被邀请进入'以外'。你一生可以落笔三篇。”她打开网站，注册了一个匿名身份（系统自动生成了一个诗意的名字）。进入“草稿箱”，她开始写第一篇——关于初恋，那个在毕业那天没有说出再见的人。

**高潮：** 写了三天草稿后，她决定“落笔”。屏幕上出现一行字：“在落笔前，我们想陪你安静一会儿。”一分钟静默倒计时。然后三个问题浮现：“你确定这是你想留下的故事吗？”“你准备好和它告别了吗？”“落笔后，它将永远在那里。”她点了确认。一声轻柔的笔落纸声。散步动画——一个人影在雨中走远。

**结局：** 小晚感觉胸口轻了一点。她关闭页面，没有再回来。但她知道，她的故事永远在那里，像刻在石头上的字。

**此旅程揭示的需求：** 邮箱邀请机制、匿名身份生成、草稿编辑、完整落笔仪式（静默→三问→笔落纸声→散步动画）

### 旅程二：阿远 —— 三篇都用完的人（深度用户路径）

**开场：** 阿远，35 岁，在「以外」开放写作功能后第一时间注册。他的第一篇写得很快——关于大学时最好的朋友，因为工作调动失去了联系。第二篇他写了很久——关于母亲去世后，才发现自己从未真正理解过她。第三篇……他犹豫了整整一个月。

**上升：** 第三篇的草稿箱里只有一行字：“给那个我从来没有勇气说出口的名字。”他反复编辑，又反复删除。每次打开草稿，都看到那行字，都觉得还不够。

**高潮：** 某个深夜，他终于写下完整的故事。落笔仪式中，三问出现时他停顿很久。最后一个问题“落笔后，它将永远在那里”让他重新审视：三篇用完了，这就是全部了。

**结局：** 落笔完成后，页面显示：“你的一生的故事，已经落笔。”阿远关掉页面。此后他偶尔回来读别人的故事，按下“共鸣”按钮——像有人在黑暗中点了一下头。

**此旅程揭示的需求：** 三篇限制的边界体验、草稿长期保存、落笔后的“已毕业”状态、共鸣按钮的克制交互

### 旅程三：小晨 —— 只读不写的访客（读者路径）

**开场：** 小晨，28 岁，在社交媒体上看到有人说“每天只更新一篇故事”。她好奇地点进去。页面极简，没有导航、没有信息流、没有搜索——只有一篇故事。她读完了，故事写的是一个人对已故宠物的告别。

**上升：** 第二天她又来了，是另一篇故事。这次是关于一段没有结果的暗恋。她看完后，页面底部有一个很轻的按钮，点了一下，屏幕上短暂出现一个光点然后消散。她意识到：有人在世界的某个角落，也和她被同一篇故事触动了。

**高潮：** 一周后，她在页面底部看到“我想落笔”。她输入邮箱，加入了等待列表。

**结局：** 小晨成为了潜在的写作者。她还没有故事要讲，但她知道，当那天到来时，「以外」会在那里等着她。

**此旅程揭示的需求：** 随机单篇展示、共鸣按钮（光点动画）、邮箱收集、极简只读界面

### 旅程四：创作者 —— 管理种子内容（运营者路径）

**开场：** 创作者（Yang），作为独立开发者，需要在概念验证阶段亲自落笔第一篇种子故事。他打开管理后台，用和正常用户相同的仪式流程落笔——因为他相信，第一篇文章必须真诚，不能是假内容。

**上升：** 落笔完成后，他需要决定这篇故事什么时候展示。管理后台允许他：选择“立即展示”或设定展示日期。概念验证阶段每天只能展示一篇，多余的排入队列。

**高潮：** 随着等待列表增长，他需要查看：多少人注册了邮箱、多少人读过故事、有没有人通过社交媒体自发传播。数据看板保持极简——只看核心指标。

**结局：** 当积累足够种子故事后，他可以开放写作功能，将管理权限降到最低——因为「以外」的设计哲学就是“不需要管理员”。

**此旅程揭示的需求：** 管理员后台（极简）、故事队列管理、等待列表查看、基础数据看板

### 旅程需求汇总

| 旅程 | 核心需求 |
|------|----------|
| 小晚（落笔者） | 邮箱邀请、匿名身份、草稿编辑、落笔仪式全流程 |
| 阿远（深度用户） | 三篇限制体验、草稿长期保存、毕业状态、共鸣按钮 |
| 小晨（读者） | 随机展示、共鸣交互、邮箱收集、只读界面 |
| 创作者（运营者） | 管理后台、故事队列、等待列表、数据看板 |

## 创新与新颖模式

### 检测到的创新领域

**1. 极致稀缺机制（一生三篇）**

现有内容平台的设计逻辑是"鼓励更多创作"，「以外」反其道而行——每人一生只能落笔三篇。这不是功能限制，而是价值观表达：**当平台限制你只能说三句话时，你说的每一句都会是经过深思的、真实的。** 这种机制在现有数字产品中没有先例。

**2. 反社交设计（Anti-social Design）**

所有社交平台都在做加法（评论、关注、推荐、信息流），「以外」做减法——无评论、无关注、无搜索、无信息流。这不是"没有功能"，而是刻意的设计选择：通过移除所有社交噪音，保护每个故事的重量感和私密性。这种设计哲学挑战了"内容平台必须有社交互动"的行业假设。

**3. 仪式化发布行为（落笔仪式）**

现有平台的发布按钮追求"零摩擦"——一键发送、即时可见。「以外」将发布重塑为告别仪式：一分钟静默 → 三个温和问题 → 笔落纸声 → 散步动画。这不是增加操作步骤，而是将"发布"这个行为从技术动作转化为情感仪式。

**4. "毕业"而非"留存"**

现有产品追求日活、留存、用户黏性。「以外」的设计目标是让用户用完就走——三篇落笔完毕就"毕业"，平台不需要用户回来。这种"反留存"设计在商业产品中几乎不存在。

### 市场背景与竞争格局

「以外」不属于任何现有产品品类。最接近的参照物是：
- **树洞应用**（如 Whisper、Soul）：但树洞把匿名变成社交，「以外」把匿名变成独处
- **日记应用**（如 Day One）：但日记是私人记录，「以外」是被见证的公开故事
- **慢社交产品**（如 Slowly）：但 Slowly 仍追求通信频率，「以外」追求极致稀缺

真正的竞争不是同类产品，而是"人们如何处理错过的情感"——日记、写信、倾诉、遗忘。「以外」提供了第五种选择。

### 验证方法

| 创新假设 | 验证方式 | 成功标准 |
|----------|----------|----------|
| 一生三篇能提升内容质量 | 概念验证阶段对比：有限制 vs 无限制的写作质量 | 限制组平均写作时长 > 30 分钟 |
| 反社交设计能增强故事重量感 | 用户访谈：阅读体验与社交平台的对比 | 用户主动提及"这里不一样" |
| 仪式化流程能创造情感释放 | 落笔后反馈收集 | ≥ 60% 用户报告"轻了一点" |
| "毕业"设计不影响传播 | 毕业用户的自发推荐率 | 毕业用户推荐转化率 > 普通用户 |

### 风险与兜底

| 风险 | 兜底方案 |
|------|----------|
| 用户觉得三篇太少，注册后不写 | 草稿无限制，允许长期酝酿；概念验证阶段先展示种子内容验证阅读需求 |
| 反社交设计导致用户无法互动 | 共鸣按钮作为唯一克制互动——一个光点亮起然后消散，足以传递"有人和你一样" |
| 仪式流程太长导致流失 | 落笔仪式可在三问后保存退出，下次继续；仪式是"最后一次确认"而非障碍 |
| "反留存"导致产品无增长 | 毕业用户的自发传播恰恰是最有力的推荐——"我用完了我的一生三篇" |

## Web 应用特定需求

### 项目类型概览

「以外」是以 Web 为第一形态的内容平台，核心价值在于仪式化的阅读与写作体验。技术选型必须服务于情感体验——页面加载不能打断沉浸感，动画和音效必须流畅，跨设备访问必须一致。

### 浏览器与设备矩阵

| 优先级 | 平台 | 浏览器 | 备注 |
|--------|------|--------|------|
| 一级 | 移动端 | Safari（iOS 15+）、Chrome（Android 10+） | 主要入口，情感阅读场景多为手机 |
| 二级 | 桌面端 | Chrome、Safari、Firefox、Edge | 深度写作场景 |
| 三级 | 平板端 | iPad Safari | 兼顾阅读与写作 |

- **形态选择：** 单页应用（SPA），保证仪式流程的流畅过渡和状态管理
- **响应式设计：** 移动优先，断点覆盖 320px - 1440px
- **PWA 支持：** 概念验证阶段不做，第二版考虑离线草稿编辑

### 性能目标

详见「非功能需求 > 性能」章节。

### 搜索引擎策略

- **概念验证阶段：** 不需要搜索引擎优化——稀缺感来自口碑传播，不来自搜索流量
- **第二版：** 选择性索引——公开故事页面可被索引，用户个人空间不索引
- **分享元数据：** Open Graph 和 Twitter Card 必须精心设计——分享链接的预览文案本身就是传播素材（"每天只有一篇故事，读完就没了"）

### 可访问性

详见「非功能需求 > 可访问性」章节。

### 实现考量

- **架构模式：** SPA，前端框架待定（React/Vue/Svelte 均可）
- **状态管理：** 落笔仪式流程需要精确的状态机控制（静默 → 三问 → 确认 → 动画）
- **音频：** Web Audio API 实现笔落纸声，需预加载音频资源
- **动画：** CSS 动画 + JS 动画结合，散步动画可能需要 Canvas 或 SVG
- **存储：** 草稿自动保存（LocalStorage 或 IndexedDB），防止意外丢失
- **邮箱收集：** 概念验证阶段仅需表单提交 + 邮件验证

## 项目范围界定与分阶段开发

### 最小可行产品策略与理念

**最小可行产品策略：** 体验验证型——概念验证网站不做写作功能，只做阅读体验验证。核心假设是：「以外」的阅读体验（极简、克制、沉浸）能否引发情感共鸣和自发传播。如果阅读端无法打动人，写作端就没有意义。

**资源需求：** 一人全栈开发（Yang），预计 2-4 周完成概念验证网站

### 第一阶段：概念验证网站（最小可行产品）

**支撑的用户旅程：** 小晨（读者路径）、创作者（运营者路径）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 单篇故事展示 | 每天展示一篇种子故事，极简排版 | 必须 |
| 响应式界面 | 手机 + 桌面 + 平板自适应 | 必须 |
| 邮箱收集 | "我想落笔"表单，收集等待列表 | 必须 |
| 品牌标识 | 未闭合圆符号 + 品牌标语 | 必须 |
| 分享元数据 | 社交分享预览文案 | 必须 |
| 管理后台 | 故事队列管理、邮箱列表查看 | 必须 |
| 基础数据看板 | 访问量、邮箱数、故事阅读数 | 应有 |

**不做：** 用户注册、落笔功能、仪式流程、共鸣按钮

### 第二阶段：开放写作（增长版）

**支撑的用户旅程：** 小晚（落笔者）、阿远（深度用户）

| 功能 | 说明 |
|------|------|
| 一生三篇机制 | 注册 + 落笔计数 + 永久锁定 |
| 完整仪式流程 | 静默 → 三问 → 笔落纸声 → 散步动画 |
| 匿名身份生成 | 系统自动生成诗意名字，无需手机号 |
| 草稿编辑 | 草稿箱、自动保存、长期保留 |
| 随机故事展示 | 每次访问随机展示一篇 |
| 共鸣按钮 | 唯一互动——光点亮起然后消散 |
| 合上功能 | 隐藏已读故事 |
| 邮箱邀请 | 等待列表批量邀请机制 |

### 第三阶段：远期扩展（不承诺时间线）

|------|------|

### 风险缓解策略

| 风险类型 | 具体风险 | 缓解方案 |
|----------|----------|----------|
| **技术风险** | 仪式动画在低端手机上卡顿 | 概念验证阶段不实现动画，仅用静态页面 + 音效；第二版按设备性能分级渲染 |
| **市场风险** | 概念验证网站无人传播 | 种子故事质量是关键——Yang 亲自落笔，确保第一篇文章足够真诚；同时选择有传播力的社交平台投放 |
| **资源风险** | 独立开发者时间不足 | 概念验证网站控制在 2-4 周内完成；后端用成熟托管服务降低运维成本 |
| **产品风险** | 邮箱列表增长缓慢 | 允许读者"转发给朋友"机制，让稀缺感变成传播动力 |

## 功能需求

### 内容展示与阅读

- FR1: 访客可以每天阅读一篇展示中的故事
- FR2: 访客可以通过分享链接直接访问特定故事
- FR3: 已注册用户可以每次访问时随机阅读一篇故事
- FR4: 已注册用户可以"合上"已读故事，不再展示给自己
- FR5: 访客可以查看社交分享链接的预览文案（品牌标语 + 故事摘要）

### 等待列表与邀请

- FR6: 访客可以在页面底部输入邮箱加入等待列表
- FR7: 访客提交邮箱后可以收到确认邮件
- FR8: 管理员可以从等待列表中批量邀请用户注册
- FR9: 被邀请的用户可以通过邮件中的链接完成注册

### 用户身份与账户

- FR10: 被邀请用户可以通过邮箱注册匿名账户
- FR11: 系统可以为新注册用户自动生成一个诗意的匿名名字
- FR12: 用户可以查看自己已使用的落笔次数（共三次）
- FR13: 三篇全部落笔后，用户可以进入"已毕业"状态
- FR14: 已毕业用户仍可以登录并阅读他人故事

### 内容创作与管理

- FR15: 用户可以创建故事草稿
- FR16: 用户可以在草稿箱中编辑和保存草稿
- FR17: 系统可以自动保存用户的草稿内容，防止意外丢失
- FR18: 用户可以将草稿推进到落笔仪式
- FR19: 用户一生最多只能完成三次落笔
- FR20: 故事落笔后永久锁定，不可删除、不可编辑
- FR21: 落笔后的故事可以被其他用户随机阅读

### 落笔仪式

- FR22: 用户在落笔前可以经历一分钟静默倒计时
- FR23: 静默结束后，系统可以向用户展示三个确认问题
- FR24: 用户回答确认问题后可以完成落笔
- FR25: 落笔完成时系统可以播放笔落纸声音效
- FR26: 落笔完成后系统可以展示散步动画
- FR27: 用户可以在仪式流程中途退出并保存进度

### 社交互动（克制型）

- FR28: 已注册用户可以对故事按下"共鸣"按钮
- FR29: 共鸣触发后展示一个光点亮起然后消散的动画
- FR30: 共鸣次数对其他用户不可见
- FR31: 平台不提供评论功能
- FR32: 平台不提供关注功能
- FR33: 平台不提供搜索功能
- FR34: 平台不提供信息流功能
- FR35: 平台不提供通知系统（无推送、无提醒、无消息中心）

- FR36: 已注册用户首次进入时可以体验引导流程（"你心里有没有一个无法替代的人？"）

### 运营管理

- FR37: 管理员可以管理故事展示队列（排序、设定展示日期）
- FR38: 管理员可以查看等待列表（邮箱、注册时间）
- FR39: 管理员可以查看基础数据看板（访问量、邮箱数、故事阅读数）
- FR40: 管理员可以用与正常用户相同的仪式流程落笔种子故事

### 可访问性与兼容

- FR41: 仪式动画可以为偏好减少动效的用户提供降级方案
- FR42: 音效可以为选择静音的用户关闭
- FR43: 界面在不同屏幕尺寸下保持一致的阅读体验

## 非功能需求

### 性能

- NFR1: 首屏加载时间 < 2 秒（含故事正文渲染）
- NFR2: 用户交互响应时间 < 100 毫秒（共鸣按钮、落笔确认等）
- NFR3: 单篇故事切换加载时间 < 500 毫秒
- NFR4: 仪式动画在主流设备上保持 60fps 帧率
- NFR5: 音频资源（笔落纸声）预加载完成时间 < 1 秒

### 安全与隐私

- NFR6: 用户邮箱在数据库中以加密形式存储
- NFR7: 所有数据传输使用加密协议
- NFR8: 管理员后台需要独立的身份验证机制
- NFR9: 故事内容与用户身份的关联数据不可被外部批量获取
- NFR10: 落笔后的故事数据不可被管理员删除或修改（系统级约束）

### 可靠性

- NFR11: 故事数据零丢失——落笔后的内容必须有持久化备份
- NFR12: 系统可用性 ≥ 99.9%（月度计算）
- NFR13: 草稿数据在客户端离线状态下不丢失（本地缓存）
- NFR14: 数据库备份频率不低于每日一次

### 可扩展性

- NFR15: 概念验证阶段支持 1000 日活用户，无需架构调整
- NFR16: 第二版支持 10000 日活用户，性能降级 < 10%
- NFR17: 存储架构支持故事数据永久增长（无上限设计）

### 可访问性

- NFR18: 符合 WCAG 2.1 AA 级标准
- NFR19: 所有动画支持 `prefers-reduced-motion` 媒体查询降级
- NFR20: 音效提供用户可控的静音开关
- NFR21: 文字排版对比度符合 AA 级最低要求

### 可维护性

- NFR22: 独立开发者可在一人维护下完成日常运维（无单点故障）
- NFR23: 部署流程自动化——代码推送到主分支后自动部署
- NFR24: 日志和监控覆盖关键路径，异常可在 30 分钟内发现
